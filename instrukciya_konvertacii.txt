=====================================================================
ИНСТРУКЦИЯ ПО КОНВЕРТАЦИИ МОДЕЛИ YOLOv8:  pt  ->  onnx  ->  rknn
Целевое устройство: Orange Pi 5B (SoC RK3588S)
=====================================================================


---------------------------------------------------------------------
ОБЩАЯ СХЕМА
---------------------------------------------------------------------
1) Обучение модели		-> Google Colab		-> файл best.pt
2) Конвертация pt->onnx->rknn	-> ПК с Linux (x86_64) 	-> файл .rknn
3) Запуск модели					-> Orange Pi 5B

ВАЖНО: шаги конвертации (1 и далее по этой инструкции) выполняются
ТОЛЬКО на ПК с архитектурой x86_64 под Linux, а НЕ на самой плате.
Пакет rknn-toolkit2 (конвертер) существует только под x86_64 Linux.
На плате он не установится. Поэтому конвертируем на ПК, а на плату
переносим уже готовый файл .rknn.

Обозначения:
  ~            = домашняя папка пользователя (например /home/cvlab)
  <ПОЛЬЗОВАТЕЛЬ> = имя вашего пользователя в системе


=====================================================================
ШАГ 0. ЧТО НУЖНО ПОДГОТОВИТЬ ДО НАЧАЛА
=====================================================================
- ПК с Linux Ubuntu (20.04 или 22.04), архитектура x86_64.
- Python 3.10.
- Файл best.pt, полученный после обучения в Google Colab
  (скачать с Google Drive на ПК).
- ~200 изображений для калибровки (кадры, похожие на ваше боевое
  видео - тот же ракурс/освещение). Понадобятся на ШАГЕ 4.

КЛЮЧЕВОЙ НЮАНС ПРО ВЕРСИИ:
  Версия rknn-toolkit2 на ПК = 2.3.2.
  Она ОБЯЗАНА совпадать с версией librknnrt.so, установленной на
  плате Orange Pi. При несовпадении версий модель на плате не
  запустится (ошибка init_runtime). Мы фиксируем версию 2.3.2 везде.


=====================================================================
ШАГ 1. НАСТРОЙКА ОКРУЖЕНИЯ НА ПК
=====================================================================
ГДЕ: ПК x86_64 Linux, терминал.

Команды:

    mkdir ~/rknn_project && cd ~/rknn_project

    # Два репозитория:
    #  - форк airockchip нужен для экспорта NPU-совместимого ONNX
    #  - rknn_model_zoo нужен для конвертации в RKNN и постобработки
    git clone https://github.com/airockchip/ultralytics_yolov8.git
    git clone https://github.com/airockchip/rknn_model_zoo.git

    # Отдельное изолированное окружение (чтобы не было конфликтов)
    python3 -m venv venv
    source venv/bin/activate

    # Конвертер. Версия 2.3.2 = как librknnrt.so на плате.
    pip install rknn-toolkit2==2.3.2

    # Зависимости форка. ВНИМАНИЕ: файла requirements.txt в форке НЕТ,
    # он переехал в pyproject.toml. Поэтому ставим сам пакет так:
    pip install -e ./ultralytics_yolov8

    # Дополнительно для экспорта ONNX:
    pip install onnx onnxslim

НЮАНСЫ:
  - Форк требует numpy ниже 2.0. Это совпадает с требованием
    rknn-toolkit2, поэтому конфликта версий НЕ будет (в отличие от
    попытки установки в Google Colab).
  - Если команда "pip install -e ." выдаст ошибку сборки на старом
    ПК - сначала обновите pip и повторите:
        pip install --upgrade pip setuptools wheel
  - Окружение venv должно быть активировано (source venv/bin/activate)
    на всех последующих шагах. Признак активации - "(venv)" в начале
    строки терминала.


=====================================================================
ШАГ 2. ПОЛОЖИТЬ ФАЙЛ best.pt НА ПК
=====================================================================
ГДЕ: ПК, файловый менеджер или браузер.

Скачайте обученные веса best.pt из Google Drive
(папка MyDrive/yolo_traffic/train/weights/best.pt) и положите в:

    ~/rknn_project/best.pt


=====================================================================
ШАГ 3. ЭКСПОРТ  pt -> onnx  (NPU-совместимый ONNX)
=====================================================================
ГДЕ: ПК, папка форка ~/rknn_project/ultralytics_yolov8.

ЗАЧЕМ ЭТОТ ШАГ ОСОБЫЙ:
  Обычный экспорт Ultralytics зашивает в граф "хвост" YOLOv8 (декод
  DFL), который NPU не поддерживает - он уходит на CPU и роняет
  скорость в разы. Форк airockchip обрезает этот хвост и отдаёт
  "сырой" 9-выходной ONNX (3 масштаба x 3 ветви). Декод потом
  делается в постобработке на CPU.

НЮАНС ПЕРЕД ЗАПУСКОМ (обязательно!):
  Экспортёр берёт путь к модели из конфигурационного файла.
  Откройте файл:
        ~/rknn_project/ultralytics_yolov8/ultralytics/cfg/default.yaml
  Найдите строку, начинающуюся с "model:" (по умолчанию там
  "model: yolov8n.pt") и впишите полный путь к вашим весам:
        model: /home/<ПОЛЬЗОВАТЕЛЬ>/rknn_project/best.pt
  Сохраните файл.

Команды:

    cd ~/rknn_project/ultralytics_yolov8
    export PYTHONPATH=./
    python ./ultralytics/engine/exporter.py

РЕЗУЛЬТАТ:
  Рядом с best.pt появится файл best.onnx.

ПРОВЕРКА КОРРЕКТНОСТИ:
  В логе экспорта модель должна иметь 9 выходных тензоров (по 3 на
  каждый из трёх масштабов). Если выход один - значит сработал
  обычный экспорт, а не форк (проверьте, что запускали именно
  exporter.py из папки форка).


=====================================================================
ШАГ 4. ПОДГОТОВКА КАЛИБРОВОЧНОЙ ВЫБОРКИ (для INT8)
=====================================================================
ГДЕ: ПК, терминал.

ЗАЧЕМ: при квантизации в INT8 нужен список ~200 репрезентативных
картинок, по которым подбираются диапазоны значений. От качества
этой выборки напрямую зависит точность модели после квантизации.

Команды:

    mkdir ~/rknn_project/calib_images
    # Скопируйте в эту папку ~200 изображений, похожих на боевое
    # видео (тот же ракурс камеры/освещение). Затем составьте список:
    find ~/rknn_project/calib_images -name '*.jpg' > ~/rknn_project/dataset.txt

НЮАНС:
  Берите кадры вашего датасета/видео, а НЕ посторонние картинки.
  Калибровка на неподходящих изображениях (например на COCO) даёт
  просадку точности на 10-30%.


=====================================================================
ШАГ 5. КОНВЕРТАЦИЯ  onnx -> rknn  (с квантизацией INT8)
=====================================================================
ГДЕ: ПК, папка ~/rknn_project/rknn_model_zoo/examples/yolov8/python.

НЮАНС ПЕРЕД ЗАПУСКОМ (обязательно!):
  Скрипт конвертации по умолчанию калибрует по COCO. Нужно указать
  ему ваш список калибровки.
  Откройте файл:
        ~/rknn_project/rknn_model_zoo/examples/yolov8/python/convert.py
  Найдите в начале файла переменную DATASET_PATH и замените её
  значение на путь к вашему списку:
        DATASET_PATH = '/home/<ПОЛЬЗОВАТЕЛЬ>/rknn_project/dataset.txt'
  Сохраните файл.

Команды:

    cd ~/rknn_project/rknn_model_zoo/examples/yolov8/python
    python convert.py ~/rknn_project/best.onnx rk3588 i8 ~/rknn_project/yolov8_vehicles.rknn

СИНТАКСИС КОМАНДЫ convert.py:
    python convert.py <onnx_model> <ПЛАТФОРМА> <тип> <выходной_файл.rknn>
  где:
    <onnx_model>      - путь к вашему best.onnx
    <ПЛАТФОРМА>       - rk3588 (для RK3588S тоже пишется rk3588)
    <тип>             - i8  = с квантизацией в INT8 (наш случай)
                        fp  = без квантизации (для сравнения точности)
    <выходной_файл>   - куда сохранить готовую .rknn

РЕЗУЛЬТАТ:
  Файл ~/rknn_project/yolov8_vehicles.rknn - это готовая модель.

ПРОВЕРКА КОРРЕКТНОСТИ:
  В логе сборки посмотрите распределение слоёв. Свёрточные слои
  должны лечь на NPU. Если много слоёв ушло на CPU (CPU-fallback) -
  это узкое место (обычно означает, что ONNX экспортирован не форком,
  см. ШАГ 3).

=====================================================================
ЧТО ДАЛЬШЕ (кратко, уже на плате)
=====================================================================
Конвертация на этом закончена. Дальнейшие шаги - на самой плате:

1) Перенести файл yolov8_vehicles.rknn на Orange Pi (через облако,
   флешку или scp).

2) На плате установить рантайм для инференса (ВЕРСИЯ 2.3.2, как
   при конвертации):
        pip3 install rknn-toolkit-lite2==2.3.2

3) Проверить, что версия librknnrt.so на плате = 2.3.2:
        strings /usr/lib/librknnrt.so | grep "librknnrt version"
   При несовпадении - заменить librknnrt.so на файл версии 2.3.2.

4) Запускать инференс скриптом на rknn-toolkit-lite2 (RKNNLite).

ВАЖНЫЙ НЮАНС ЗАПУСКА НА ПЛАТЕ:
  Модель ждёт 4-мерный вход (1, 640, 640, 3). Перед подачей кадра в
  модель нужно добавить ось пакета:
        img = np.expand_dims(img, 0)
  Иначе будет ошибка: "input[0] need 4dims input, but 3dims".
